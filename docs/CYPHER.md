# Cypher and graph algorithms

Every query Blastradius depends on, copied from `packages/graph` (this file is generated by `packages/graph/scripts/gen-cypher-doc.ts`, which takes each query string from the code and runs it live). For each query: the question it answers, the hackathon track, the FalkorDB feature it shows, and **real output** captured from FalkorDB 6.0.2.

> Sample outputs come from the hand-written test fixture (`packages/graph/test/fixture.ts`: 9 services, 10 PRs incl. a renovate[bot] PR, 2 incidents with runbooks, an ADR chain, a thread and a ticket), loaded under the `docs` graph namespace with **model** embeddings. They can be regenerated against the data team's real snapshot later.

## Conventions

- One graph per tenant: `blastradius_acme`, `blastradius_globex`. Setting `BLASTRADIUS_GRAPH_NAMESPACE=ns` prefixes the key (`ns_blastradius_acme`); tests use `itest`, this doc uses `docs`.
- Every value is a parameter (`$service`). Only labels, relationship types and validated hop counts are interpolated, after `assertLabel` / `assertRelType` / an integer range check.
- Read tools use `GRAPH.RO_QUERY` (the client's `roQuery`), so they cannot write.
- Every node leaving `packages/graph` is identified by its `uid` (`Service:cart`). FalkorDB internal ids never leave the package: `src/convert.ts` is the single converter, and edges reference node uids.
- Every tool returns `GraphToolResult` with `cypher` exactly as sent, `params`, plain-JSON `rows` and evidence `paths` (from `MATCH p = …` or `shortestPath`). The query vector `$vec` is reported as `<384-dim embedding of $text>`; `$text` itself is in `params`.
- Vector scores are cosine **distances** (lower = closer); rows show `similarity = 1 - distance` (clamped) and `distance`.
- The server's default query timeout is 1000 ms. Tool queries take 1–60 ms on the fixture and on a synthetic 11k-node / 26k-edge graph (`scripts/scale-check.ts`: who_knows 8 ms, blast_radius at 6 hops 21 ms). Bulk loads pass `TIMEOUT 60000`.

<a id="blast_radius"></a>
### blast_radius: what else breaks?

- **Question:** If `$service` fails, which services break (or, with `direction: dependencies`, what could be the upstream cause)?
- **Track:** 01
- **FalkorDB feature:** variable-length paths `DEPENDS_ON*1..N` + `algo.betweenness`

DEPENDS_ON points caller → callee, so the services that break are the ones with a path INTO the failing service. Betweenness ranks them by how much traffic flows through them. The hop cap is interpolated (Cypher cannot parameterise `*1..N`) after validation as an integer 1..6.

Input `{"service":"cart"}`:

```cypher
// Q1 "What else breaks if $service fails?"
// 1) betweenness centrality over the whole dependency graph (chokepoints score high)
CALL algo.betweenness({nodeLabels: ['Service'], relationshipTypes: ['DEPENDS_ON']})
YIELD node, score
WITH node AS svc, score AS betweenness
// 2) keep the services within 3 DEPENDS_ON hops of the alerting service
MATCH (s:Service {uid: $service})
MATCH p = (svc)-[:DEPENDS_ON*1..3]->(s)
WHERE svc <> s
// 3) one (shortest) evidence path per affected service
WITH svc, betweenness, p ORDER BY length(p) ASC
WITH svc, betweenness, collect(p)[0] AS path
OPTIONAL MATCH (team:Team)-[:OWNS]->(svc)
RETURN svc.uid AS service, svc.name AS name, length(path) AS hops, betweenness,
       svc.tier AS tier, team.name AS team, path
ORDER BY betweenness DESC, hops ASC
```
params: `{"service":"Service:cart"}`

**Real output** (fixture, 3.8 ms): _2 services within 3 hops of Service:cart (dependents); top: checkout (betweenness 3)_

```json
{"service":"Service:checkout","name":"checkout","hops":1,"betweenness":3,"tier":1,"team":"Checkout Team"}
{"service":"Service:frontend","name":"frontend","hops":1,"betweenness":0,"tier":1,"team":"Web Team"}
```
Evidence paths: 2. First: `Service:checkout -[:DEPENDS_ON]-> Service:cart`

### critical_services: chokepoints

- **Question:** Which services sit on the most dependency paths?
- **Track:** 01
- **FalkorDB feature:** `algo.betweenness({nodeLabels, relationshipTypes})`

Input `{"limit":5}`:

```cypher
// Which services are chokepoints? Betweenness centrality on Service/DEPENDS_ON,
// plus how many services call each one (dependents) and how many it calls.
CALL algo.betweenness({nodeLabels: ['Service'], relationshipTypes: ['DEPENDS_ON']})
YIELD node, score
OPTIONAL MATCH (caller:Service)-[:DEPENDS_ON]->(node)
WITH node, score, count(DISTINCT caller) AS dependents
```

<a id="suspect_changes"></a>
### suspect_changes: what probably caused it?

- **Question:** Which recent PRs touched the alerting service or something it depends on?
- **Track:** 01
- **FalkorDB feature:** derived `TOUCHES` edges + zero-or-more hop `DEPENDS_ON*0..N`; time window from the newest PR

"Recent" is measured back from `max(PR.mergedAt)` in the graph, not from today, so the frozen snapshot keeps working. Humans sort before bots unless `includeBots`. The evidence path is `Person-AUTHORED->PR-TOUCHES->Service<-DEPENDS_ON-…-alert service`.

Input `{"service":"cart"}`:

```cypher
// Q2 "What probably caused the alert on $service?"
// Recent merged PRs that touched the service, or a service it depends on
// (up to 2 DEPENDS_ON hops), newest first. "Recent" = within $sinceDays of
// the newest PR in the graph.
MATCH (latest:PR)
WITH max(latest.mergedAt) AS newest
MATCH (alert:Service {uid: $service})
MATCH p = (author:Person)-[:AUTHORED]->(pr:PR)-[:TOUCHES]->(svc:Service)<-[:DEPENDS_ON*0..2]-(alert)
WHERE pr.mergedAt >= newest - $sinceDays * 86400000
// keep the closest service each PR reaches the alert through
WITH pr, author, svc, p, length(p) - 2 AS hops
ORDER BY hops ASC
WITH pr, author, collect(svc.uid)[0] AS service, min(hops) AS hops, collect(p)[0] AS path
OPTIONAL MATCH (pr)-[:MODIFIES]->(f:File)
WITH pr, author, service, hops, path, collect(f.path) AS files
RETURN pr.uid AS pr, pr.number AS number, pr.title AS title, pr.mergedAt AS mergedAt,
       author.uid AS author, author.name AS authorName, coalesce(pr.isBot, author.isBot, false) AS isBot,
       service, hops, files, pr.additions AS additions, pr.deletions AS deletions, pr.url AS url, path
// humans first unless bots were asked for, then newest first
ORDER BY CASE WHEN $includeBots THEN 0 WHEN isBot THEN 1 ELSE 0 END ASC,
         mergedAt DESC
LIMIT $limit
```
params: `{"service":"Service:cart","sinceDays":30,"includeBots":false,"limit":10}`

**Real output** (fixture, 3.4 ms): _2 PRs in the 30 days before the newest PR touched Service:cart or its dependencies; newest suspect: PR #140 "cart: reduce Valkey connection pool size" by Alice Chen_

### who_knows: who can fix it / who knows X

- **Question:** Who knows the service (or a free-text topic) best?
- **Track:** 01, 03
- **FalkorDB feature:** `algo.pageRank` combined with authorship activity; full-text on PR titles for topics

**Why PageRank is used this way.** `algo.pageRank(label, relType)` is directed and takes one label and one type. Authorship edges point Person → PR, so on the authorship graph alone every person gets the same teleport score (we verified: three authors with 1, 1 and 2 PRs all scored 0.333). So we run PageRank over the **whole company graph** (`null, null`): a person gains rank only through incoming edges (incidents they RESPONDED_BY, decisions DECIDED_BY them, threads/issues that MENTION them, findings SUPPORTED_BY them). That is a global "the organisation keeps pointing at this person" signal. We then combine it with service-specific activity:

```
activity  = # of the person's PRs that TOUCH the service (or match the topic)
authority = 0.5 + 0.5 × pagerank / max(pagerank among candidates)    ∈ [0.5, 1]
score     = activity × authority × (0.1 if bot else 1)
```

Activity decides who is a candidate and dominates the order; authority breaks ties and can at most double a score. Bots are excluded unless `includeBots` (then ×0.1). `onCall` = has the ON_CALL_FOR edge of the newest rotation week ≤ today.

Input `{"service":"checkout"}`:

```cypher
// Q3 "Who knows / can fix $service?"
MATCH (s:Service {uid: $service})
// the current rotation week for this service: newest weekStart <= today
OPTIONAL MATCH (:Person)-[w:ON_CALL_FOR]->(s)
WHERE w.weekStart <= $today
WITH s, max(w.weekStart) AS currentWeek
// authority: PageRank over the whole company graph (see the comment in people.ts)
CALL algo.pageRank(null, null) YIELD node, score
WITH s, currentWeek, node AS person, score AS authority
WHERE person:Person AND ($includeBots OR NOT coalesce(person.isBot, false))
// activity: the person's PRs that touch the service
MATCH p = (person)-[:AUTHORED]->(pr:PR)-[:TOUCHES]->(s)
// most recent PR first, so collect(p)[0] is the person's latest evidence path
WITH currentWeek, person, authority, pr, p ORDER BY pr.mergedAt DESC
WITH currentWeek, person, authority, count(DISTINCT pr) AS prs, max(pr.mergedAt) AS lastActiveAt, collect(p)[0] AS path
// normalise authority against the strongest candidate: 0.5 .. 1.0
WITH currentWeek, max(authority) AS maxAuthority,
     collect({person: person, authority: authority, prs: prs, lastActiveAt: lastActiveAt, path: path}) AS cands
UNWIND cands AS c
WITH currentWeek, c.person AS person, c.prs AS prs, c.lastActiveAt AS lastActiveAt, c.path AS path,
     c.authority AS pagerank, 0.5 + 0.5 * c.authority / maxAuthority AS authority
OPTIONAL MATCH (person)-[:MEMBER_OF]->(team:Team)
WITH currentWeek, person, prs, lastActiveAt, path, pagerank, authority, collect(team) AS teams
WHERE $team IS NULL OR any(t IN teams WHERE t.uid = $team OR t.slug = $team)
// on call = has the current week's ON_CALL_FOR edge (for $service, or any service for a topic)
OPTIONAL MATCH (person)-[oc:ON_CALL_FOR {weekStart: currentWeek}]->(ocs:Service)
WHERE $service IS NULL OR ocs.uid = $service
WITH person, prs, lastActiveAt, path, pagerank, authority, teams, count(oc) > 0 AS onCall
WHERE NOT $onCallOnly OR onCall
RETURN person.uid AS person, person.name AS name,
       prs * authority * (CASE WHEN coalesce(person.isBot, false) THEN 0.1 ELSE 1.0 END) AS score,
       prs, pagerank, authority, [t IN teams | t.name][0] AS team, onCall, lastActiveAt,
       coalesce(person.isBot, false) AS isBot, path
ORDER BY score DESC, lastActiveAt DESC
LIMIT $limit
```
params: `{"service":"Service:checkout","team":null,"includeBots":false,"onCallOnly":false,"today":"2026-10-14","limit":5}`

### on_call: who is on call

- **Question:** Who is on call for the service at a given date (default today; falls back to the newest week ≤ date)?
- **Track:** 01
- **FalkorDB feature:** one `ON_CALL_FOR {weekStart}` edge per week, compared as ISO date strings

Input `{"service":"cart","at":"2025-09-24"}`:

```cypher
// Who is on call for $service at $at? One ON_CALL_FOR edge per week:
// take the newest rotation week that started on or before $at.
MATCH (s:Service {uid: $service})
MATCH (:Person)-[w:ON_CALL_FOR]->(s)
WHERE w.weekStart <= $at
WITH s, max(w.weekStart) AS week
MATCH p = (person:Person)-[oc:ON_CALL_FOR {weekStart: week}]->(s)
OPTIONAL MATCH (person)-[:MEMBER_OF]->(team:Team)
RETURN person.uid AS person, person.name AS name, oc.weekStart AS weekStart,
       team.name AS team, s.uid AS service, p AS path
ORDER BY name
```
params: `{"service":"Service:cart","at":"2025-09-24"}`

<a id="service_context"></a>
### service_context: the context card

- **Question:** What is one hop around this service (team, owners, deps, dependents, runbooks, docs, incidents, decisions)?
- **Track:** 01, 03
- **FalkorDB feature:** pattern comprehensions (one row, no row multiplication)

FalkorDB 6.0.2 quirk we hit: a pattern comprehension that binds a relationship variable (e.g. `[(s)-[d:DEPENDS_ON]->(x) | d.protocol]`) makes later comprehensions in the same RETURN come back empty. So edge properties are collected with OPTIONAL MATCH + collect first, and the comprehensions bind nodes only.

Input `{"service":"cart"}`:

```cypher
// Context card for $service: everything one hop away, in one row.
// Edge properties (DEPENDS_ON.protocol) are collected with OPTIONAL MATCH first:
// on FalkorDB 6.0.2 a pattern comprehension that binds a relationship variable
// makes LATER comprehensions in the same RETURN come back empty (verified).
MATCH (s:Service {uid: $service})
OPTIONAL MATCH (team:Team)-[:OWNS]->(s)
WITH s, collect(team)[0] AS team
OPTIONAL MATCH (s)-[d1:DEPENDS_ON]->(callee:Service)
WITH s, team, collect({uid: callee.uid, name: callee.name, protocol: d1.protocol}) AS dependsOn
OPTIONAL MATCH (caller:Service)-[d2:DEPENDS_ON]->(s)
WITH s, team, dependsOn, collect({uid: caller.uid, name: caller.name, protocol: d2.protocol}) AS dependents
// pattern comprehensions collect each neighbour kind without multiplying rows
RETURN s.uid AS service, s.name AS name, s.kind AS kind, s.tier AS tier, s.language AS language,
       s.description AS description, team.uid AS team, team.name AS teamName,
       [(team)<-[:MEMBER_OF]-(m:Person) WHERE NOT coalesce(m.isBot, false) | {uid: m.uid, name: m.name}] AS owners,
       dependsOn, dependents,
       [(rb:Runbook)-[:APPLIES_TO]->(s) | {uid: rb.uid, title: rb.title, steps: rb.steps}] AS runbooks,
       [(doc:Doc)-[:ABOUT]->(s) | {uid: doc.uid, title: doc.title, kind: doc.kind}] AS docs,
       [(i:Incident)-[:AFFECTED]->(s) | {uid: i.uid, title: i.title, severity: i.severity, startedAt: i.startedAt}] AS recentIncidents,
       [(dec:Decision)-[:ABOUT]->(s) | {uid: dec.uid, title: dec.title, status: dec.status}] AS decisions,
       // evidence: the 1-hop edges themselves
       [p = (s)-[:DEPENDS_ON]-(:Service) | p] + [p = (s)<-[:OWNS]-(:Team) | p] +
       [p = (s)<-[:APPLIES_TO]-(:Runbook) | p] + [p = (s)<-[:ABOUT]-(:Doc) | p] +
       [p = (s)<-[:ABOUT]-(:Decision) | p] + [p = (s)<-[:AFFECTED]-(:Incident) | p] AS paths
```
params: `{"service":"Service:cart"}`

<a id="past_incidents"></a>
### past_incidents: what worked last time

- **Question:** Which incidents hit this service (or a direct neighbour), what caused them and which runbook fixed them?
- **Track:** 01, 02
- **FalkorDB feature:** multi-hop expansion `Incident-AFFECTED->Service`, `-CAUSED_BY->PR`, `-RESOLVED_BY->Runbook`

Reads procedural memory: seed incidents and incidents the Scribe wrote via `closeIncident`.

Input `{"service":"cart"}`:

```cypher
// Q4 "What worked last time on $service?" Incidents that AFFECTED the service
// (or a direct DEPENDS_ON neighbour), with cause PR, runbook and responders.
MATCH (s:Service {uid: $service})
MATCH p = (i:Incident)-[:AFFECTED]->(svc:Service)-[:DEPENDS_ON*0..1]-(s)
WITH i, svc, p, length(p) - 1 AS hops ORDER BY hops ASC
WITH i, collect(svc.uid)[0] AS service, min(hops) AS hops, collect(p)[0] AS affectedPath
OPTIONAL MATCH cp = (i)-[:CAUSED_BY]->(pr:PR)
WITH i, service, hops, affectedPath, collect(pr.uid)[0] AS causedBy, collect(cp)[0] AS causePath
OPTIONAL MATCH rp = (i)-[:RESOLVED_BY]->(rb:Runbook)
WITH i, service, hops, affectedPath, causedBy, causePath, collect(rb)[0] AS rb, collect(rp)[0] AS runbookPath
OPTIONAL MATCH (i)-[:RESPONDED_BY]->(person:Person)
WITH i, service, hops, affectedPath, causedBy, causePath, rb, runbookPath, collect(person.uid) AS responders
RETURN i.uid AS incident, i.title AS title, i.severity AS severity, i.status AS status,
       i.startedAt AS startedAt, service, hops, causedBy,
```

### recordEpisode: episodic memory, safe under concurrency

`seq` is computed inside the write query from the session's current last Episode. FalkorDB executes writes to one graph one at a time and each query is atomic, so concurrent appends to one session get distinct, gap-free seqs (the integration test fires 5 in parallel and gets 0..4).

```cypher
// Append an Episode to the session's chain. seq is computed INSIDE the write
// query (FalkorDB serialises writes per graph), so concurrent appends are safe.
MATCH (s:Session {sessionId: $sessionId})
OPTIONAL MATCH (s)-[:HAS_EPISODE]->(prev:Episode)
WITH s, prev ORDER BY prev.seq DESC LIMIT 1
WITH s, prev, CASE WHEN prev IS NULL THEN 0 ELSE prev.seq + 1 END AS seq
CREATE (ep:Episode {uid: 'Episode:' + $sessionId + ':' + toString(seq), sessionId: $sessionId, seq: seq,
                    agent: $agent, kind: $kind, summary: $summary, at: $now})
CREATE (s)-[:HAS_EPISODE]->(ep)
FOREACH (_ IN CASE WHEN prev IS NULL THEN [] ELSE [1] END | CREATE (prev)-[:NEXT]->(ep))
RETURN ep.uid AS uid, seq
```

```cypher
MATCH (s:Service {uid: $service})
MERGE (i:Incident {uid: $incidentUid})
SET i += $incident, i.startedAt = coalesce(sess.startedAt, $now), i.embedding = vecf32($vec)
MERGE (rb:Runbook {uid: $runbookUid})
SET rb += $runbook
MERGE (i)-[:AFFECTED]->(s)
MERGE (i)-[:RESOLVED_BY]->(rb)
MERGE (rb)-[:APPLIES_TO]->(s)
MERGE (sess)-[:INVESTIGATES]->(i)
SET sess.status = 'closed', sess.closedAt = $now
WITH i
// the PR that caused it (if known)
OPTIONAL MATCH (pr:PR {uid: $causedByPr})
FOREACH (_ IN CASE WHEN pr IS NULL THEN [] ELSE [1] END | MERGE (i)-[:CAUSED_BY]->(pr))
WITH DISTINCT i
// the people who responded
OPTIONAL MATCH (p:Person) WHERE p.uid IN $responders
WITH i, collect(p) AS people
FOREACH (x IN people | MERGE (i)-[:RESPONDED_BY]->(x))
RETURN i.uid AS incidentUid
```

### recall_memory: recall across sessions

- **Question:** what did OTHER sessions learn about this service / question? **Track:** 02
- **FalkorDB feature:** graph walk + vector index (Finding, Incident) in one `CALL { … UNION ALL … }` query; the current session is excluded in every branch.

Run from session B, right after session A was closed:

```cypher
// Recall memory from OTHER sessions: findings + resolved incidents with runbooks,
// each with the path that connects it to the service / question
CALL {
  // findings other sessions recorded ABOUT the service
  MATCH p = (s:Service {uid: $service})<-[:ABOUT]-(f:Finding)
  WHERE $sessionId IS NULL OR f.sessionId <> $sessionId
  RETURN 'finding' AS kind, f.uid AS uid, f.claim AS title, f.kind AS summary, f.sessionId AS sessionId,
         f.agent AS agent, null AS runbook, null AS distance, f.createdAt AS createdAt, p AS path
  UNION ALL
  // resolved incidents on the service and the runbook that fixed them (procedural memory)
  MATCH p = (s:Service {uid: $service})<-[:AFFECTED]-(i:Incident)-[:RESOLVED_BY]->(rb:Runbook)
  WHERE i.status = 'resolved' AND ($sessionId IS NULL OR coalesce(i.sessionId, '') <> $sessionId)
  RETURN 'incident' AS kind, i.uid AS uid, i.title AS title, i.summary AS summary, i.sessionId AS sessionId,
         null AS agent, {uid: rb.uid, title: rb.title, steps: rb.steps} AS runbook, null AS distance,
         coalesce(i.resolvedAt, i.startedAt) AS createdAt, p AS path
  UNION ALL
  // findings whose claim is semantically close to $text (vector index on Finding)
  CALL db.idx.vector.queryNodes('Finding', 'embedding', $k, vecf32($vec)) YIELD node AS f, score
  WITH f, score WHERE $sessionId IS NULL OR f.sessionId <> $sessionId
  OPTIONAL MATCH p = (f)-[:ABOUT]->()
  WITH f, score, collect(p)[0] AS p
  RETURN 'finding' AS kind, f.uid AS uid, f.claim AS title, f.kind AS summary, f.sessionId AS sessionId,
         f.agent AS agent, null AS runbook, score AS distance, f.createdAt AS createdAt, p AS path
  UNION ALL
  // resolved incidents semantically close to $text, with their runbook
  CALL db.idx.vector.queryNodes('Incident', 'embedding', $k, vecf32($vec)) YIELD node AS i, score
  WITH i, score WHERE i.status = 'resolved' AND ($sessionId IS NULL OR coalesce(i.sessionId, '') <> $sessionId)
  MATCH p = (i)-[:RESOLVED_BY]->(rb:Runbook)
  RETURN 'incident' AS kind, i.uid AS uid, i.title AS title, i.summary AS summary, i.sessionId AS sessionId,
         null AS agent, {uid: rb.uid, title: rb.title, steps: rb.steps} AS runbook, score AS distance,
         coalesce(i.resolvedAt, i.startedAt) AS createdAt, p AS path
}
RETURN kind, uid, title, summary, sessionId, agent, runbook, distance, createdAt, path
ORDER BY createdAt DESC
```
params: `{"sessionId":"docs_session_b","service":"Service:cart","k":10,"text":"cart valkey pool errors","vec":"<384-dim embedding of $text>"}`

## Loading

`loadSnapshot(tenant, snap, {reset, embed})`: reset (GRAPH.DELETE) → ensureSchema → nodes by label → relationships by (type, source label, target label) → derive TOUCHES → embeddings. Batches: 500 nodes, 1000 edges, 50 vectors per query, each with `TIMEOUT 60000`. Fixture load: `{"nodes":47,"edges":90,"touches":12,"embedded":7,"ms":902}`.

Node upsert (per label, e.g. Service):
```cypher
// Upsert Service nodes by uid (batched)
UNWIND $rows AS row
MERGE (n:Service {uid: row.uid})
SET n += row.props
```
Relationship upsert (per type and endpoint labels; both endpoints labelled so MATCH uses the uid index):
```cypher
// Upsert Service-[:DEPENDS_ON]->Service relationships (batched)
UNWIND $rows AS row
MATCH (a:Service {uid: row.from})
MATCH (b:Service {uid: row.to})
MERGE (a)-[r:DEPENDS_ON]->(b)
SET r += row.props
```
ON_CALL_FOR is MERGEd on `weekStart`, one edge per person/service/week:
```cypher
// Upsert Person-[:ON_CALL_FOR]->Service relationships (batched)
UNWIND $rows AS row
MATCH (a:Person {uid: row.from})
MATCH (b:Service {uid: row.to})
MERGE (a)-[r:ON_CALL_FOR {weekStart: row.props.weekStart}]->(b)
SET r += row.props
```
Derived TOUCHES (full load, then the incremental variant used by `ingestDelta`):
```cypher
// Derive (PR)-[:TOUCHES {files}]->(Service) for every PR
MATCH (pr:PR)-[:MODIFIES]->(f:File)-[:PART_OF]->(s:Service)
WITH pr, s, count(DISTINCT f) AS files
MERGE (pr)-[t:TOUCHES]->(s)
SET t.files = files
RETURN count(t) AS touches
```
```cypher
// Derive (PR)-[:TOUCHES {files}]->(Service) for the given PRs
UNWIND $prs AS prUid
MATCH (pr:PR {uid: prUid})-[:MODIFIES]->(f:File)-[:PART_OF]->(s:Service)
WITH pr, s, count(DISTINCT f) AS files
MERGE (pr)-[t:TOUCHES]->(s)
SET t.files = files
RETURN count(t) AS touches
```
Embeddings (text = `EMBED_TEXT_FIELDS[label]` joined by newlines):
```cypher
// Store embeddings as vecf32 (feeds the Incident vector index)
UNWIND $rows AS row
MATCH (n:Incident {uid: row.uid})
SET n.embedding = vecf32(row.vec)
```
The tenant's "now" (used by suspect_changes):
```cypher
// The tenant's "now": the merge time of the newest PR in the graph
MATCH (pr:PR)
RETURN max(pr.mergedAt) AS newest
```
`ingestDelta` (incremental re-ingest, Track 03) runs the same upserts without a reset, derives TOUCHES only for the delta's PRs and embeds only the delta's text nodes.
