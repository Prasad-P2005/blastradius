# Blastradius data

Two tenants, each one FalkorDB graph: **real public git history** plus a **seeded synthetic organisation** on top.
Everything here is generated by `packages/ingest` (`pnpm data:build`) and loaded with `pnpm graph:load`.

| File | What |
|---|---|
| `acme.json` | tenant **acme** = [open-telemetry/opentelemetry-demo](https://github.com/open-telemetry/opentelemetry-demo) (1,100 nodes, 5,368 edges, 1.0 MB) |
| `globex.json` | tenant **globex** = [GoogleCloudPlatform/microservices-demo](https://github.com/GoogleCloudPlatform/microservices-demo) (1,362 nodes, 6,784 edges, 1.3 MB) |
| `scenarios.json` | 11 demo scenarios (`Scenario[]`): 4 incident + 2 ask for acme, 3 incident + 2 ask for globex |
| `deltas/<tenant>.json` | real PRs held back for the "keeping knowledge current" demo (`add-prs`) |

Format: `Snapshot` / `SnapshotNode` / `SnapshotEdge` in `packages/shared/src/index.ts` (SPEC §2). One node or edge per line, keys sorted.

## Real vs synthetic, field by field

`synthetic: false` = real (from git, or curated from the repo's own files). `synthetic: true` = generated with seeded randomness and hand-written prose.

| Label | Real / synthetic | Fields |
|---|---|---|
| Service | **real, curated** | `name`, `slug`, `language`, `kind`, `repoPath`, `description` (paraphrased from repo docs), `deployment` (globex k8s name). `tier` is our judgement, informed by acme's `service.criticality`. |
| File | **real** | `path`, `service` (via the alias table below), `language` (from the extension) |
| PR | **real** | `number`, `title`, `sha` (squash/merge commit), `mergedAt` (committer time), `additions`/`deletions`/`filesChanged` (whole PR, from `git log --numstat`), `url`, `authorName`, `isBot` |
| Person | **real** | `name` as written in commit metadata, `slug`, `isBot`, `prCount`/`firstSeenAt`/`lastSeenAt` (within the snapshot). No emails. |
| DEPENDS_ON | **real, curated** | `protocol`, `source` = the compose / k8s / config file it was read from (`packages/ingest/src/deps.ts`) |
| AUTHORED, MODIFIES, PART_OF | **real** | from git; `MODIFIES {additions, deletions}` per file |
| TOUCHES | derived at load | by `packages/graph` from MODIFIES→PART_OF; not in the files |
| Team, OWNS, MEMBER_OF | **synthetic** | teams and anchor services are curated; remaining services join by author overlap; each human joins the team whose services they touched most |
| ON_CALL_FOR | **synthetic** | weekly rotation over each team's top ≤5 members, 12 weeks before the newest PR **through 2027-12-31** (one edge per person, service and week) |
| Incident, Alert, Runbook | **synthetic**, anchored to real PRs | 9 per tenant; each `CAUSED_BY` a real **human** PR that touches the affected service; responders are the PR author plus owning-team members; runbooks name real deployments, flags and datastores |
| Decision, Doc (ADRs) | **synthetic text**, real decisions | 8 (acme) / 7 (globex); each `JUSTIFIES` the real PRs that implemented it (e.g. acme ADR-001 ← #1619 "Replace Redis with Valkey"). Context, reasons and wording are ours. |
| Issue, Thread | **synthetic** | 24 tickets and 22–24 chat threads per tenant: hand-written (decision arguments, ask answers), one per incident, plus templates grounded in real PRs and the real top authors of each service. Every reference is a `MENTIONS` edge. |

Synthetic prose attributes fictional messages to real public contributors in their real roles (author of a PR, frequent contributor to a service). It is clearly marked `synthetic: true`, and none of it claims to be a real quote.

## Service alias tables

A file is part of a service if its path starts with one of the service's prefixes (longest match wins). Files matching nothing (docs, CI, Helm, root compose files) get no File node.

**acme** (`src/<dir>/`): every service maps to its own dir (`src/cart/` → `cart`, `src/product-catalog/` → `product-catalog`, …) plus the pre-2025 names (`src/cartservice/`, `src/checkoutservice/`, `src/productcatalogservice/`, `src/frontendproxy/`, `src/otelcollector/`, …; renamed in PRs #1858–#1867). Special cases: `src/postgresql/` → `astronomy-db` (datastore); `valkey-cart` has no source dir (stock image). Services: frontend-proxy, frontend, checkout, cart, payment, product-catalog, currency, shipping, quote, email, ad, recommendation, accounting, fraud-detection, image-provider, kafka (queue), valkey-cart, astronomy-db (datastores), flagd, flagd-ui, load-generator, otel-collector, grafana, jaeger, prometheus, opensearch, opamp-server, telemetry-docs, agent, mcp, chatbot, react-native-app.

**globex** (k8s name → slug): `src/frontend/` → frontend, `src/checkoutservice/` → checkout, `src/cartservice/` → cart, `src/productcatalogservice/` → product-catalog, `src/currencyservice/` → currency, `src/paymentservice/` → payment, `src/shippingservice/` → shipping, `src/emailservice/` → email, `src/recommendationservice/` → recommendation, `src/adservice/` → ad, `src/shoppingassistantservice/` → shopping-assistant, `src/loadgenerator/` → load-generator; datastores `redis-cart` and `alloydb` have no source dir.

**Dependencies left out on purpose:** service → otel-collector (telemetry export), service → flagd / opamp-server (control plane), frontend-proxy → load-generator (UI route only). See the header of `deps.ts`.

## People and bots

Person uid = `Person:<slug of name>`. Characters NFKD can't decompose are transliterated first (`Piotr Kiełkowicz` → `piotr-kielkowicz`). Obvious aliases are merged (`smeet07` → `smeet-nagda`, `GarethE` → `gareth`). Bots stay in the graph as real history with `isBot: true`: names ending in `[bot]` or ` Bot`, or containing dependabot, renovate (Mend/WhiteSource Renovate), github-actions, otelbot, copybara. acme: 227 human / 378 bot PRs; globex: 175 human / 926 bot PRs.

## Seed and determinism

Seeds: acme **1337**, globex **4242** (recorded in each file). A small mulberry32 PRNG drives all synthetic choices (forked per concern). "Now" is the newest PR's merge time; nothing reads the wall clock or `Math.random`. Running `data:build` twice produces byte-identical files (sha256 prefixes: acme `2acef16810e24f6b`, globex `9b5308b71f9bc6f7`, scenarios `9b63146b4832cc91`, deltas `63cfdb4e409b4b68` / `48a348c4161c7dd8`).

## Regenerate, validate, load

```bash
pnpm data:build          # clone → snapshot → synth → validate (writes data/*.json)
pnpm graph:load          # ensureSchema + loadSnapshot for both tenants (--tenant acme, --reset false, --no-embed)
pnpm --filter @blastradius/ingest add-prs --tenant acme              # apply data/deltas/acme.json via ingestDelta
pnpm --filter @blastradius/ingest add-prs --tenant acme --from-git   # git fetch; PRs after the pinned SHA, newest 50
pnpm --filter @blastradius/ingest verify-scenarios --with-deltas --markdown
pnpm --filter @blastradius/ingest test   # validator, PRNG, path/people/time unit tests
```

The validator checks label/type whitelists, uid format and key match, required props per label, `synthetic` on every node, epoch-ms `*At`, edge endpoint existence and allowed endpoint labels, no TOUCHES or embeddings, Monday `weekStart`s and on-call coverage of the **current real week**, scenario references, and scans every file for email addresses (the only tolerated pattern is image-density file names like `App-Icon-1024x1024@1x.png`). `load` records an `ingest_jobs` row in Postgres best-effort.

## Deltas and the scenarios

Scenarios are defined against the **canonical snapshot** (what `pnpm graph:load` loads). `add-prs` moves the tenant's newest PR forward, which moves the 30-day `suspect_changes` window:

- **acme** delta: 23 PRs (human #3966, #4083, #4084, #4087, #4088), window moves 6 days. All scenarios still meet the SPEC §10 bar afterwards. For cart and checkout the new #1 suspect becomes **#4087** ("Add metric cardinality overflow visibility and a cart-service demo flag", touching ValkeyCartStore.cs). That is the intended re-ingest demo (`acme-cart-errors` presenter note).
- **globex** delta: 49 PRs (human #2538, #2568, #2578, #2588, #2598, #2599), window moves 6 weeks (to 2024-05-20…06-19). The globex suspects fall out of the window, so **globex incident scenarios hold only before `add-prs`**. Re-run `pnpm graph:load` to reset.

## Scenario verification

`verify-scenarios` loads each tenant fresh and runs the real tools through `runTool` (embeddings: `model`, Xenova/all-MiniLM-L6-v2). Checks per SPEC §10: (a) blast radius ≥ 2, (b) expected suspect PR in the top 3 of `suspect_changes` with default args, (c) a human in the top 3 of `who_knows`, (d) ≥1 past incident from `past_incidents`/`similar_incidents`. We also check (n) that the expected suspect, expert and past incident are each the **#1** row, because the scripted agents narrate the #1 row (agents request #2). For ask scenarios, an expected source must be in the top 3 of `ask_company` and (n) #1.

**Result on the canonical snapshot: 11/11 PASS, including (n).** With `EMBEDDINGS=hash` the canonical result is also 11/11 for the SPEC bar. After deltas: acme passes the SPEC bar 6/6 (cart and checkout fail only (n), because #4087 is new and on top, as intended); globex fails (b) in its 3 incident scenarios as explained above.

The agents' own report (`pnpm --filter @blastradius/agents scenarios`, scripted pipeline): **11 scenarios, all 43 checks passed**; the cause / precedent / expert findings name exactly the `expected` items.
